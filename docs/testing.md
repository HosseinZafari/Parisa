# آزمون و پذیرش محلی

## آزمون‌های خودکار

```sh
npm run setup
npm test
```

این فرمان آزمون‌های pytest، بررسی Svelte و ساخت خروجی Vite را اجرا می‌کند. آزمون‌های بک‌اند برای هر مورد یک SQLite موقت با محدودیت‌های واقعی و تراکنش مشابه برنامه می‌سازند؛ دادهٔ محلی شما پاک نمی‌شود. ارتباط سرویس زبانی و اینستاگرام واقعی در آن‌ها شبیه‌سازی شده است.

پوشش متمرکز شامل تطبیق محصول، استخراج مشخصات، پرسیدن فقط اطلاعات ناقص، اصلاح مشتری، تأیید خلاصه، اعتبارسنجی نشانی، ایجاد سفارش، رزرو موجودی، هر چهار نتیجهٔ پرداخت، انقضای زمانی، callback تکراری و هم‌زمان، امضای جعلی پرداخت، تغییر مبلغ، پرداخت تکمیلی، تأیید و رد تغییر، مسئول و زمان تصمیم، جلوگیری از ارسال برای هر مانع، پیگیری و ابطال، احراز هویت، مبدأ نامعتبر، اعلان بدون تکرار، پایداری پس از بستن و بازکردن موتور پایگاه، امضای اینستاگرام، پیام تکراری، حساب اشتباه، echo، schema مدل، خطای سرویس و سقف پیام است.

## آزمون مرورگر

در یک ترمینال `npm run dev` را اجرا کنید. در ترمینال دیگر:

```sh
cd frontend
npx playwright install chromium
npm run test:e2e
```

در ویندوز از Chrome نصب‌شده استفاده می‌شود. در لینوکس Chromium دانلودشده استفاده می‌شود؛ با `PLAYWRIGHT_CHANNEL` می‌توان کانال نصب‌شده را انتخاب کرد. در صورت نیاز متغیرهای `E2E_USERNAME` و `E2E_PASSWORD` را در محیط ترمینال خود تنظیم کنید.

آزمون مرورگر سه مسیر را پوشش می‌دهد: داشبورد، کاتالوگ، پنجرهٔ قابل بستن با Escape و نمایش موبایل؛ مسیر کامل گفتگو، اصلاح، خلاصه، پرداخت، callback تکراری، درخواست تغییر، پرداخت تکمیلی، آماده‌سازی، ارسال و پیگیری؛ و ساخت، ویرایش و غیرفعال‌کردن محصول دارای مشخصات. خطاهای JavaScript نیز بررسی می‌شوند. این آزمون عمداً سفارش و محصول آزمایشی در پایگاه محلی می‌سازد؛ برای اجرای جدا، از پایگاه اختصاصی یا بازنشانی محیط نمایشی پس از توقف برنامه استفاده کنید. تصاویر در `artifacts` و گزارش شکست در `frontend/test-results` ذخیره می‌شوند.

## بررسی دستی

| معیار | مسیر بررسی |
| --- | --- |
| اجرای بدون کلید و بدون ابر | setup و dev با `.env.example` |
| سفارش محلی کامل | نمونهٔ پیام README، اصلاح و تأیید خلاصه |
| استخراج با سرویس واقعی | تنظیم LLM_MODE=api و آزمون جمله‌های فارسی با کلید خودتان |
| چند محصول مشابه | محصول دوم با alias مشترک و انتخاب نام دقیق |
| سؤال فقط برای دادهٔ مفقود | مشخصات را در یک پیام بدهید و سؤال بعدی را ببینید |
| موفق/ناموفق/لغو/انقضا | دکمه‌های درگاه آزمایشی؛ برای هر نتیجه پیوند تازه |
| اثر یکتای پرداخت | دکمهٔ تأیید تکراری، سپس بررسی اعلان و مبلغ |
| صف اولویت و تأخیر | سفارش نمایشی دیرشده بالاتر از بقیه است |
| تغییر و حفظ نسخهٔ قبلی | در گفتگوی ثبت‌شده درخواست تعداد/نشانی تازه بدهید |
| تأیید و پرداخت اضافه | پیش‌نمایش مبلغ، تأیید فروشنده و تسویهٔ مانده |
| رد تغییر | ثبت دلیل و مشاهدهٔ آن در گفتگو/پیگیری |
| منع ارسال | درخواست باز یا ماندهٔ پرداخت؛ دکمهٔ ارسال مسدود می‌ماند |
| ارسال معتبر | آماده‌سازی، آمادهٔ ارسال، کد رهگیری و تأیید تحویل |
| دوام داده | برنامه را متوقف و دوباره اجرا کنید؛ سفارش و پیام‌ها باقی می‌مانند |
| پیگیری خصوصی | مرورگر ناشناس و سپس ابطال پیوند توسط فروشنده |
| مشتری تکراری | همان گفتگو، سفارش جدید و تکرار سفارش، تأیید نشانی |
| ارجاع انسانی | «فروشنده»، پاسخ از گفتگوهای میز کار، فعال‌سازی دستیار |
| اینستاگرام واقعی | چک‌لیست جداگانهٔ docs/instagram.md با حساب مجاز |
| استقرار | بررسی اعتبار و هزینه، سلامت و HTTPS روی میزبان انتخاب‌شده |

نبود کلید سرویس زبانی، مجوز متا و دسترسی AWS به معنی تأیید اتصال واقعی آن سرویس‌ها نیست. آزمون‌های محلی و شبیه‌سازی جای آزمون زندهٔ حساب شما را نمی‌گیرند.

## وابستگی‌ها

نسخه‌های مستقیم Python در requirements و نسخه‌های رابط در package-lock ثبت شده‌اند. هنگام نصب اولیه، npm سه هشدار با شدت پایین در زنجیرهٔ **ابزار توسعهٔ Vite/Svelte** گزارش کرد؛ اصلاح خودکار عرضه‌شده‌ای در گزارش آن نسخه وجود نداشت. این بسته‌ها در خروجی ایستای مرورگر منتشر نمی‌شوند. پیش از انتشار عمومی، بررسی وابستگی‌ها و به‌روزرسانی سازگار را دوباره انجام دهید.
