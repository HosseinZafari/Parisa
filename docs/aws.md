# استقرار کم‌هزینه روی AWS

هیچ منبع AWS در جریان ساخت پروژه ایجاد نشده و حساب، اعتبار و دسترسی سرویس‌های شما هنوز بررسی نشده‌اند. فایل‌های این پوشه مسیر استقرار را آماده می‌کنند. پیش از ساخت هر منبع، نتیجهٔ بررسی حساب و قیمت همان منطقه را ثبت کنید.

## بررسی طرح، اعتبار و سرویس‌های مجاز

براساس [پرسش‌های رسمی Free Tier](https://aws.amazon.com/free/free-tier-faqs/)، حساب‌های جدید واجد شرایط می‌توانند تا ۲۰۰ دلار اعتبار دریافت کنند؛ مدت طرح رایگان و انقضای اعتبار یکسان نیستند و شرایط حساب‌های قدیمی متفاوت است. در ۴ نوامبر ۲۰۲۶، برنامهٔ حساب‌های جدید طرح رایگان حداکثر شش‌ماهه دارد. **این ارقام، تأیید رایگان‌بودن حساب شما نیستند.**

در کنسول Billing بخش‌های Free Tier، Credits، Account plan و Bills را ببینید. با AWS CLI جدید و نمایهٔ مخصوص آزمایش نیز می‌توان بررسی فقط‌خواندنی را انجام داد:

```sh
python -X utf8 deploy/aws_preflight.py
```

این ابزار هویت حساب، طرح، اعتبار باقی‌مانده، مصرف Free Tier و بودجه‌های موجود را می‌خواند. به مجوزهای خواندن STS، Free Tier و Budgets نیاز دارد. اگر فرمان طرح در حساب/نسخهٔ ابزار موجود نباشد، خروجی نامشخص است و باید از کنسول بررسی شود؛ رایگان فرض نمی‌شود. قرارداد فرمان در [مرجع رسمی GetAccountPlanState](https://docs.aws.amazon.com/cli/latest/reference/freetier/get-account-plan-state.html) آمده است.

پیش از استقرار این جدول را برای حساب خود تکمیل کنید:

| مورد | نتیجهٔ لازم |
| --- | --- |
| شناسه و منطقهٔ حساب | حساب آزمایشی و منطقهٔ انتخاب‌شده |
| تاریخ ساخت و نوع طرح | قدیمی/جدید، رایگان/پرداختی و تاریخ پایان |
| اعتبار | مانده، تاریخ انقضا و پوشش سرویس موردنظر |
| دسترسی سرویس | امکان ساخت Lightsail یا EC2 در همین طرح و منطقه |
| قیمت نهایی | مبلغ ماشین، دیسک، شبکه، نشانی عمومی، لاگ و پشتیبان |
| سقف هزینه | مثلاً ۱۰ دلار ماهانه به همراه هشدار |

## معماری پیشنهادی برای آزمایش

یک ماشین کوچک Linux در Lightsail، دو کانتینر روی همان میزبان: Caddy برای HTTPS و یک سرویس FastAPI که خروجی ساخته‌شدهٔ Svelte را نیز ارائه می‌کند. SQLite در volume پایدار است. RDS، Load Balancer، NAT Gateway، S3 و CloudWatch در مسیر پایه لازم نیستند. این انتخاب خرابی یک ماشین را تحمل نمی‌کند؛ برای نمونهٔ آزمایشی یک حساب ساده نگه داشته شده است.

اگر Lightsail در طرح شما مجاز یا مشمول اعتبار نیست، پیش از ارتقا به طرح پرداختی، EC2 کوچک واجد شرایط حساب را با مجموع هزینهٔ EBS و IPv4 مقایسه کنید. هیچ سرویس را فقط به‌دلیل برچسب Free Tier رایگان فرض نکنید.

## برآورد نمونه

قیمت‌های بستهٔ Linux با IPv4 در [صفحهٔ رسمی Lightsail](https://aws.amazon.com/lightsail/pricing/) هنگام بررسی ۴ نوامبر ۲۰۲۶، برای ۵۱۲ مگابایت ۵ دلار، ۱ گیگابایت ۷ دلار و ۲ گیگابایت ۱۲ دلار ماهانه بودند. بسته شامل سهم دیسک و انتقال است؛ قیمت و سهم منطقهٔ شما باید دوباره بررسی شود. برای این نمونه، ۱ گیگابایت نقطهٔ شروع عملی‌تری است؛ ساخت تصویر را روی دستگاه محلی انجام دهید تا حافظهٔ ماشین کوچک مصرف نشود. کوچک‌ترین بستهٔ IPv4 ارزان‌تر است، اما حافظهٔ کمتری برای برنامه و ساخت تصویر دارد.

| جزء | فرض آزمایش | هزینهٔ مورد انتظار / خطر افزایش |
| --- | --- | --- |
| پردازش، دیسک و IPv4 | بستهٔ Linux یک گیگابایتی | حدود ۷ دلار ماهانه پیش از اعتبار و مالیات |
| پایگاه داده | SQLite روی دیسک همان ماشین | در بسته؛ رشد بیش از دیسک نیازمند ارتقا |
| HTTPS و ورودی عمومی | Caddy، درگاه‌های ۸۰ و ۴۴۳ | هزینهٔ سرویس جدا ندارد؛ دامنه جداست |
| لاگ | دو فایل حداکثر ۵ مگابایتی برای هر کانتینر | روی دیسک همان ماشین؛ انتقال به CloudWatch جدا محاسبه می‌شود |
| شبکه | در سهم انتقال بسته | مازاد انتقال یا تفاوت منطقه هزینه دارد |
| پشتیبان | دانلود نسخهٔ SQLite روی دستگاه شما | انتقال تابع سهم شبکه؛ snapshot و S3 رایگان فرض نمی‌شوند |
| دامنه | زیردامنهٔ موجود | صفر هزینهٔ افزوده در فرض دامنهٔ موجود؛ ثبت دامنه جداست |
| مدل زبانی | پیش‌فرض محلی | صفر؛ حالت API جدا و وابسته به ارائه‌دهنده است |

برآورد مسیر پایه حدود ۷ دلار ماهانه بدون سرویس اضافی است. برای دامنه، snapshot، مالیات، انتقال مازاد یا مصرف مدل باید بودجهٔ جدا در نظر گرفت. توقف ماشین الزاماً هزینه را صفر نمی‌کند؛ طبق [راهنمای صورتحساب Lightsail](https://docs.aws.amazon.com/lightsail/latest/userguide/amazon-lightsail-frequently-asked-questions-faq-billing-and-account-management.html)، برای پایان هزینه باید منابع صورتحساب‌پذیر را مطابق قواعد سرویس حذف کنید. آزمایش رایگان قدیمی Lightsail برای حساب‌های جدید، جایگزین شرایط فعلی اعتبار AWS نیست.

## هشدار بودجه

در Billing یک بودجهٔ ماهانهٔ ۱۰ دلار و هشدار مصرف واقعی ۵۰٪ و ۹۰٪ بسازید. فایل‌های JSON نمونه در `deploy` آماده‌اند؛ ایمیل را با نشانی خودتان جایگزین کنید. ساخت بودجه **عملیات نوشتن در حساب شماست** و فقط بعد از تأیید حساب و قیمت انجام می‌شود:

```sh
aws budgets create-budget --account-id YOUR_ACCOUNT_ID --budget file://deploy/budget.example.json --notifications-with-subscribers file://deploy/budget-notifications.example.json
```

هشدار بودجه سقف سخت مصرف نیست و ممکن است با تأخیر برسد. قواعد قیمت فعلی Budgets و سقف رایگان حساب را هنگام ایجاد بررسی کنید؛ این پروژه اقدام خودکار برای افزایش طرح یا ساخت سرویس ندارد.

## آماده‌سازی میزبان

۱. ماشین انتخاب‌شده را پس از بررسی هزینه ایجاد کنید. دسترسی SSH را به IP خود محدود کنید؛ فقط ۸۰ و ۴۴۳ عمومی باشند. درگاه ۸۰۰۰ و پایگاه داده عمومی نشوند. Docker Engine و افزونهٔ Compose را طبق مستندات سیستم‌عامل نصب کنید.

۲. یک زیردامنه را به IP ثابت متصل به ماشین اشاره دهید. پیش از راه‌اندازی Caddy، DNS باید درست باشد. IP بدون اتصال و snapshot فراموش‌شده ممکن است صورتحساب داشته باشند.

۳. کد را روی ماشین یا تصویر ساخته‌شده را با برچسب نسخه منتقل کنید. فایل `.env` محلی را منتقل نکنید. از ریشهٔ پروژه:

```sh
cp deploy/.env.aws.example deploy/.env.aws
chmod 600 deploy/.env.aws
```

`PUBLIC_BASE_URL` و `ALLOWED_ORIGINS` را برابر نشانی HTTPS واقعی قرار دهید. گذرواژه و PAYMENT_SECRET را تصادفی کنید. برای ساخت راز می‌توانید `python -c "import secrets; print(secrets.token_urlsafe(40))"` را روی دستگاه خود اجرا کنید. پیش‌فرض‌های استقرار باید `APP_ENV=aws`، `COOKIE_SECURE=true` و `SEED_DEMO=false` باقی بمانند.

یک فایل `deploy/.env` با دو مقدار بسازید:

```dotenv
DOMAIN=orders.your-domain.example
IMAGE_TAG=test-001
```

۴. اجرا از پوشهٔ deploy:

```sh
docker compose build
docker compose up -d
docker compose ps
```

ساخت خروجی Svelte در مرحلهٔ Node انجام می‌شود. کانتینر API با کاربر غیرریشه اجرا و پیش از شروع، `alembic upgrade head` را اجرا می‌کند. داده در volume باقی می‌ماند. Caddy گواهی HTTPS می‌گیرد. بررسی سلامت:

```sh
curl --fail https://orders.your-domain.example/api/health
docker compose logs --tail 50 app
```

پس از ورود، محصولات واقعی آزمایشی را در مدیریت محصول بسازید. دادهٔ نمایشی در محیط AWS خودکار وارد نمی‌شود. برای مدل زبانی و اینستاگرام فقط متغیرهای سرور را تنظیم و `docker compose up -d --force-recreate app` اجرا کنید. هیچ کلید AWS در برنامه لازم نیست مگر خودتان سرویس اضافه کنید.

## پشتیبان، ارتقا و بازگشت

نسخهٔ پشتیبان را با SQLite backup API بگیرید؛ کپی سادهٔ فایل هنگام WAL فعال کافی نیست. ابزار همراه پروژه:

```sh
docker compose cp backup.py app:/tmp/backup.py
docker compose exec app python /tmp/backup.py /tmp/parisa-before-update.db
docker compose cp app:/tmp/parisa-before-update.db ./parisa-before-update.db
```

پشتیبان را در دستگاه جدا نگه دارید و دسترسی آن را محدود کنید. پیش از نسخهٔ تازه، برچسب فعلی تصویر را ثبت کنید. پس از ساخت برچسب تازه، `docker compose up -d` اجرا و سلامت و یک سفارش آزمایشی را بررسی کنید. برای برگشت کد، IMAGE_TAG را به تصویر قبلی تغییر و `docker compose up -d --no-build` اجرا کنید؛ تصویر قبلی باید هنوز روی میزبان یا در registry موجود باشد.

اگر ساختار داده ناسازگار شده است، ابتدا برنامه را متوقف کنید، پشتیبان را بازیابی کنید و سپس کد متناظر را اجرا کنید. بازیابی فایل باید با توقف تمام نویسندگان، حذف کنترل‌شدهٔ WAL/SHM قدیمی و مالکیت صحیح کاربر ۱۰۰۰۱ انجام شود. پیش از هر جایگزینی، از وضعیت فعلی نیز پشتیبان بگیرید. دستور `docker compose down -v` داده را حذف می‌کند؛ برای توقف معمول از `stop` استفاده کنید.

پس از پایان آزمایش، هزینهٔ ماشین، snapshot، IP، دیسک مستقل و دامنه را جداگانه بررسی کنید. این راهنما روی حساب AWS اجرا نشده است؛ سلامت Docker و HTTPS باید روی میزبان انتخابی اعتبارسنجی شود.
