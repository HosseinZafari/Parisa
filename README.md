# پریسا؛ دفتر سفارش‌های اینستاگرام

نمونهٔ محلی و تک‌فروشنده برای تبدیل گفتگوی فارسی به سفارش قابل پیگیری. رابط با Svelte 5 و Vite، سرور با FastAPI، پایگاه دادهٔ رابطه‌ای SQLite و مهاجرت‌ها با Alembic ساخته شده است. هیچ چارچوب CSS یا کتابخانهٔ آمادهٔ رابط استفاده نشده است.

صفحهٔ پژوهش قبلی در `index.html` و منابع `docs/project-memory` و `docs/rishe-yabi-data-pack` حفظ شده‌اند. برنامهٔ جدید در `frontend` و `backend` قرار دارد.

## اجرای سریع

پیش‌نیاز: Python 3.11 یا بالاتر، Node.js 22.12 یا بالاتر و npm. Python و npm باید در مسیر فرمان باشند. نصب `uv` اختیاری است؛ در نبود آن از pip استفاده می‌شود.

در ریشهٔ پروژه:

```sh
npm run setup
npm run dev
```

بار اول `npm run dev` نیز راه‌اندازی را خودکار انجام می‌دهد. فرمان راه‌اندازی محیط مجازی، وابستگی‌ها، `.env` و پایگاه داده را می‌سازد. اجرای بعدی هیچ داده‌ای را پاک نمی‌کند. `Ctrl+C` هر دو سرویس را متوقف می‌کند.

| بخش | نشانی محلی |
| --- | --- |
| میز کار فروشنده | http://localhost:5173/dashboard |
| گفتگوی آزمایشی مشتری | http://localhost:5173/chat |
| مستندات تعاملی رابط | http://127.0.0.1:8000/docs |
| مشخصات ماشینی رابط | http://127.0.0.1:8000/openapi.json |
| سلامت پایگاه داده و سرور | http://127.0.0.1:8000/api/health |

حساب محلی پیش‌فرض: نام کاربری `parisa` و گذرواژهٔ `parisa-demo-1405`. برای استفادهٔ عمومی آن را تغییر دهید؛ تنظیمات استقرار گذرواژهٔ پیش‌فرض را نمی‌پذیرد. تغییر مقدار محیطی پس از ساخته‌شدن حساب، گذرواژهٔ ذخیره‌شده را عوض نمی‌کند؛ از فرمان تغییر گذرواژه استفاده کنید.

## یک آزمایش کامل

۱. در گفتگوی آزمایشی بنویسید: `دو عدد شمع آوا، رایحه وانیل، بزرگ، بسته‌بندی هدیه`.

۲. اطلاعات ساختگی بفرستید:

```text
نام: سارا آزمایشی؛ شهر: تهران؛ تلفن: ۰۹۱۲۰۰۰۰۰۰۰؛ آدرس: خیابان نمونه پلاک ۱۲؛ کد پستی: ۱۱۱۱۱۱۱۱۱۱
```

۳. برای اصلاح بنویسید `اصلاح تعداد: ۳`. خلاصهٔ تازه را ببینید و «تأیید خلاصه و دریافت پیوند پرداخت» را بزنید.

۴. پیوند پرداخت را باز کنید؛ موفق، ناموفق، لغو و انقضا قابل آزمایش‌اند. بعد از موفقیت، دکمهٔ تأیید تکراری نباید مبلغ یا اعلان تازه‌ای ایجاد کند.

۵. در میز کار، سفارش را باز کنید. برای آزمایش تغییر، در همان گفتگو بنویسید `تغییر تعداد: ۴`. سفارش تأییدشده تا تصمیم فروشنده ثابت می‌ماند. افزایش مبلغ، پیوند پرداخت تکمیلی ایجاد می‌کند.

۶. در صفحهٔ سفارش، آماده‌سازی را شروع و سپس وضعیت را آمادهٔ ارسال کنید. کد رهگیری را وارد و تحویل به پست را ثبت کنید. ارسال در صورت پرداخت ناقص، درخواست تغییر باز، نشانی ناقص یا موعد نامشخص مسدود می‌شود.

۷. پیوند پیگیری را در مرورگر دیگری باز کنید. یادداشت فروشنده، نشانی کامل، شمارهٔ همراه و گفتگوهای داخلی در آن منتشر نمی‌شوند. امکان ابطال یا تعویض پیوند وجود دارد.

برای سفارش تکراری در همان گفتگو: ابتدا `سفارش جدید` و بعد `تکرار سفارش`. اطلاعات قبلی برای بررسی بازیابی می‌شود و تأیید تازه لازم است. گفتگوی محلی با توکن تصادفی در مرورگر حفظ می‌شود؛ واردکردن نام مشابه باعث اتصال به حساب مشتری دیگری نمی‌شود.

## فرمان‌های توسعه

```sh
# مهاجرت پایگاه داده
python -X utf8 scripts/backend.py migrate
# دادهٔ نمونه؛ فقط وقتی کاتالوگ خالی باشد
python -X utf8 scripts/backend.py seed
# بازنشانی مخرب فقط برای محیط محلی؛ ابتدا برنامه را متوقف کنید
npm run reset-demo
# تغییر گذرواژه با ورودی مخفی و خروج همهٔ نشست‌ها
python -X utf8 scripts/backend.py set-password
# آزمون بک‌اند، بررسی Svelte و ساخت خروجی
npm test
# فقط خروجی رابط
npm run build
```

اجرای مستقل بک‌اند در ویندوز، از پوشهٔ `backend`:

```powershell
.venv\Scripts\python.exe -m app.cli migrate
.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000 --no-access-log
```

در لینوکس/مک، مسیر Python محیط مجازی `.venv/bin/python` است. اجرای مستقل رابط از `frontend`: `npm run dev`. پروکسی Vite درخواست‌های `/api` را به سرور می‌فرستد؛ کلیدها هیچ‌گاه وارد خروجی رابط نمی‌شوند.

## ساختار و محدودیت‌های عمدی

هر سفارش یک محصول با تعداد و مشخصات دارد؛ برای چند محصول، سفارش‌های جدا ثبت می‌شوند. موجودی هنگام تأیید سفارش رزرو و هنگام لغو آزاد می‌شود. سبد رهاشده به‌صورت خودکار لغو نمی‌شود؛ فروشنده سفارش پرداخت‌نشده را مدیریت می‌کند. کاهش مبلغ پس از پرداخت به‌صورت بستانکاری ثبت و با اعلان نیازمند پیگیری دستی است؛ درگاه این نمونه بازپرداخت واقعی ندارد.

پردازش محلی بدون مدل زبانی برای محصولات کاتالوگ و قالب‌های فارسی مستندشده قابل آزمایش است؛ برداشت آزاد از هر نوع جمله تضمین نمی‌شود. در حالت سرویس زبانی، خروجی JSON اعتبارسنجی می‌شود و در خطا، پردازش محلی و ارجاع به فروشنده فعال می‌ماند. ذخیرهٔ فایل تصویر در این نسخه وجود ندارد؛ پیوند تصویر مرجع ثبت می‌شود و پیوست اینستاگرام برای بررسی فروشنده ارجاع می‌شود.

استقرار این نمونه یک فرایند و یک worker دارد. SQLite، محدودکنندهٔ درخواست در حافظه و پردازش صندوق پیام برای آزمایش یک حساب مناسب‌اند. گسترش به چند نمونهٔ سرور مستلزم پایگاه داده و محدودکنندهٔ مشترک است.
